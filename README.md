# ITMO Buddy Frontend

ITMO Buddy помогает студентам ИТМО находить команду для учёбы, проектов и мероприятий. Frontend работает с REST API ITMO Buddy и получает события через SignalR.

## Возможности

- Регистрация, вход, восстановление сессии, выход и удаление аккаунта.
- Собственная и публичная анкеты, фото, видимость и серверные справочники.
- Поиск студентов, рекомендации, лайки, мэтчи, пропуск рекомендаций и блокировки.
- Общая лента и собственные объявления, создание, редактирование, закрытие и удаление.
- Отправка откликов и просмотр их статусов, принятие и отклонение кандидатов автором.
- Переписка после взаимного лайка или принятого отклика, уведомления, главная страница и настройки.

Стек включает React 19, TypeScript, Vite, React Router, TanStack Query, React Hook Form, Zod, Tailwind CSS, Radix UI и `@microsoft/signalr`.

## Локальный запуск

Нужен Node.js 20.19+ в ветке 20 либо 22.12+ и npm. Для Backend в Docker нужны Docker и Docker Compose. Откройте инструкцию Backend на зафиксированной ревизии, запустите `./scripts/dev-up.sh` из его корня и настройте доверие браузера к CA Caddy. API доступен на `https://localhost:8443`, схема на `https://localhost:8443/openapi/v1.json`. Разрешите origin `https://localhost:5173` в конфигурации Backend. [Backend и инструкции Docker](https://github.com/PrIIIcKoLyAZZZ/ITMO-Buddy-backend/tree/6c8997b74ae2394797eb0fc1493ad2f22bd5d554)

Для Frontend нужен доверенный сертификат с SAN `localhost`. Пример с установленным mkcert:

```sh
npm ci
cp .env.example .env.local
mkdir -p .cert
mkcert -install
mkcert -cert-file .cert/localhost.pem -key-file .cert/localhost-key.pem localhost
npm run dev
```

Откройте `https://localhost:5173`. Используйте `localhost` для обоих origin. Подмена одного из адресов на `127.0.0.1` меняет область действия cookie и проверяемый origin.

| Переменная | Назначение | Значение по умолчанию |
|---|---|---|
| `VITE_API_ORIGIN` | HTTPS origin для REST и SignalR без пути | `https://localhost:8443` |
| `DEV_TLS_CERT` | Путь к PEM-сертификату Vite | `.cert/localhost.pem` |
| `DEV_TLS_KEY` | Путь к PEM-ключу Vite | `.cert/localhost-key.pem` |

`VITE_*` включаются в клиентскую сборку. Храните локальные ключи и переменные в игнорируемых файлах. Vite читает TLS-файлы только при запуске dev-сервера.

## Сессия и realtime

Access token хранится в памяти вкладки. Refresh-cookie выдаётся Backend с атрибутами HttpOnly, Secure, SameSite=Strict и областью пути авторизации. При загрузке вкладки Frontend восстанавливает сессию через `POST /api/auth/refresh`. Параллельные ответы 401 используют один refresh, после которого каждый защищённый запрос может повториться один раз. При смене сессии приложение отменяет незавершённые запросы и очищает TanStack Query. Выход и удаление требуют подтверждения Backend.

На авторизованную вкладку создаётся одно SignalR-соединение с `/hubs/chat`. Long Polling передаёт токен в заголовке Authorization. После переподключения активные данные синхронизируются через REST. При недоступном SignalR чат, список диалогов и уведомления работают через REST. Переписку создаёт Backend, когда студенты взаимно ставят лайки или автор принимает отклик.

История сообщений загружается страницами по 20. Чтение истории отмечает сообщения и связанные уведомления на Backend. Для уведомления с подтверждённой связью используется точный маршрут. В остальных случаях открывается соответствующий раздел. Даты и время объявлений, сообщений и уведомлений подписаны как UTC.

## Исходники и разработка

| Путь | Ответственность |
|---|---|
| `src/api`, `src/auth`, `src/lib` | DTO, HTTP-клиент, сессия и Query Client |
| `src/profile`, `src/discovery`, `src/social` | Анкеты, справочники, поиск, рекомендации и социальные действия |
| `src/listings` | Объявления и отклики |
| `src/chat`, `src/realtime`, `src/notifications` | Диалоги, история, подписка на события и уведомления |
| `src/dashboard`, `src/settings` | Главная и настройки аккаунта |
| `src/routes.tsx`, `src/components`, `src/index.css` | Защищённые маршруты, общие компоненты и стили |

Для сквозной проверки зарегистрируйте два тестовых аккаунта в изолированных сессиях браузера. Заполните анкеты для рекомендаций. Создайте объявление от первого аккаунта, отправьте отклик со второго, примите его от первого, затем откройте существующий диалог и обменяйтесь сообщениями.

## Сборка и проверки

```sh
npm ci
npm run typecheck
npm run lint
npm run build
git diff --check
git status --short
```

`npm run build` создаёт статические файлы в `dist/`. До сборки задайте `VITE_API_ORIGIN` для целевого окружения. Опубликуйте `dist/` на HTTPS-хостинге с возвратом `index.html` для клиентских маршрутов. Настройте разрешённый origin на Backend и используйте современные браузеры с поддержкой `AbortSignal.any` и `VisualViewport`.

## Диагностика и ограничения

- При ошибке восстановления сессии проверьте готовность Backend, доверие к Caddy CA, точное совпадение разрешённого HTTPS origin и доступность cookie. Затем повторите восстановление на экране ошибки.
- Если отключён realtime, проверьте доступность `/hubs/chat` через reverse proxy и поддержку Long Polling. Защищённые запросы REST остаются доступны при работающем API.
- Содержимое справочников зависит от данных окружения. Пустой справочник факультетов не заполняется клиентом.
- После повреждения или истечения URL профиль запрашивает свежую подписанную ссылку с ограничением частоты. До загрузки используется запасной аватар.
- Состояние лайка и блокировки отображается по подтверждённым действиям текущей сессии. Списки лайков и блокировок Backend reference не предоставляет.
